# 更新日志

## 0.5.0 — 2026-10-04

**「熄屏暂停」真的会自己接上；卡片更好点**

- 修正「熄屏后暂停扫描」：打开后熄屏**或锁屏**时停下，**亮屏解锁后自动接着搬**，
  不再需要打开 App 或点通知栏。实测：熄屏 45 秒文件不动 → 亮屏但没解锁仍不动 → 解锁后几秒内自动搬完。
  （实现：亮屏广播后等 0.7 秒再问一次真实锁屏状态，避免锁屏界面还没起来时误判成"已解锁"抢跑一次。）
- 详细模式的规则卡片：点卡片任意空白处就能进编辑，不用专找「编辑」按钮。
- 「简略 / 详细」切换移到**右上角**（右手单手好点），简略模式左侧显示提示文字。

## 0.3.0 — 2026-10-04

**「写完就搬」——不再干等 30 秒稳定期**

- 新增判定：同一个文件两次看到的「大小 + 修改时间」都没变、且间隔超过判定窗口（默认 3 秒，可设 2–15 秒），
  就认为写完了，立刻搬走。
- 正在下载/正在写的文件每隔一会儿就变一次，因此**不会被误判**；原来的「文件稳定期」退居兜底。
- 发现候选但没搬走时，会在 3~4 秒后再看一次（间隔逐次拉长到稳定期为止），不会傻等下一个 5 分钟。
- 设置页新增「写完就搬」开关与「写完判定窗口」。

实测（Redmi K90 Pro Max / Android 16 / HyperOS 3）：

- 空文件放进源目录 → **16 秒**被搬走（上一版是 46 秒）
- 边写边测：文件从 200KB 一路涨到 1MB 的 **11 秒内一次都没被搬**，停笔后 11 秒才搬走，且目标文件大小完整（1,024,000 字节）

**「包含子目录」的提示更明确了**

- 不勾选 → 只搬源目录这一层，子文件夹不看（说明文字已写在编辑页）
- 勾选且目标目录在源目录里面 → 弹确认框（不勾时不会弹，因为那种情况本来就不会扫描子文件夹）

## 0.2.0 — 2026-10-04

**更快发现新图片**（原来的"按间隔轮询"整套保留，作为兜底）：

- 新增**快节奏检测**：屏幕亮着且解锁时，每 10 秒（可改 3–60 秒）看一眼源目录有没有变——
  只看目录的修改时间，不列文件、不读内容，所以很便宜；**真变了才扫**。
- 文件刚写完还没过"稳定期"时会被发现但搬不走，程序会**在稳定期过后自动再看一次**，
  不会傻等下一个 5 分钟间隔。
- 相册（MediaStore）有新增时也会立刻触发一次检测（覆盖"下载到公共目录"的情况）。
- 屏幕熄灭后自动回到每条规则自己的间隔，不额外耗电。
- 设置页新增「检测速度」一栏，可整体关掉。

实测：源目录里新建一个文件 → **46 秒后被搬进目标目录**（其中 30 秒是"稳定期"等待，
即发现+搬运实际约 16 秒），而这条规则的间隔是 5 分钟。

**两个防坑修正**：

- 目标目录（含其子目录）里的文件**不再被当成候选**。否则"目标目录在源目录里面"这种配法
  会把刚搬进去的文件一轮轮加后缀改名（`x.png → x_标签.png → x_标签_标签.png …`）。
- 规则冲突检查新增三种情况并在保存时弹确认：源=目标、目标在源里面、源在目标里面。

**其他**：

- 「设置 → 关于」的版本号改为从系统读取（之前写死成 0.1.0，升级后显示不对）。

## 0.1.0 — 2026-10-04

首个可用版本。借 Shizuku 的 shell（adb）身份，把 `Android/data/<包名>/...` 这类普通 App 进不去的目录里的图片，自动搬到指定目标目录。

### 功能

- **规则化搬运**：源目录（可含子目录、可限深度）→ 目标目录；每条规则独立开关与间隔（1–30 分钟）
- **移动 / 复制两种模式**，默认移动；首次使用建议先复制试一天
- **全自动**：`specialUse` 常驻前台服务按间隔轮询 + 打开 App 立即扫一次 + WorkManager 15 分钟兜底
- **命名安全**：非法字符清洗、来源 App 后缀（如 `封面_起点读书.png`）、超长截断（180 字节）、冲突时加时间戳/序号，**永不覆盖**
- **绝不误删**：任何失败源文件保持不动；移动模式校验失败会自动把文件移回原位
- **可撤回**：只撤"本 App 搬的、目标未被改动、源位置仍空闲"的记录，不符合条件时逐条说明原因
- **可观测**：运行日志（按规则/结果/关键字筛选）、统计计数、CSV 导出
- **可自检**：一键 6 项检查（Shizuku 通道 / 列源目录 / 目标可写 / 源目录可写改名删 / 源→目标可移动 / 环境信息），只用自己创建的临时文件
- **重复抑制**：同名文件在 30 分钟内被搬走 3 次 → 自动暂停该规则并通知（防"搬走→App 重建"死循环）
- **限速**：单轮 ≤20 张、单轮 ≤60 秒、每分钟 ≤120 张（可在设置里改）
- 界面四页全中文：规则列表 / 规则编辑（含 Shizuku 目录选择器）/ 日志 / 设置

### 技术

- Kotlin + Jetpack Compose + Room + DataStore + WorkManager + Shizuku API 13.1.5
- `minSdk 30 / targetSdk 36 / compileSdk 37`；`FOREGROUND_SERVICE_SPECIAL_USE`，不申请「所有文件访问」，无 INTERNET 权限
- App 进程不直接做任何文件操作，全部经 AIDL 交给跑在 `uid=2000(shell)` 下的 `ShituUserService`

### 实测

- 61 个 JVM 单测 + 12 个真机用例全绿（Redmi K90 Pro Max / Android 16 / HyperOS 3）
- 真机确认：能列/写别的 App 的 `Android/data`；自检 6 项全绿；复制/移动/撤回/不覆盖均符合预期
- 已知限制见 [`docs/2026-10-04-shitu-验证记录.md`](2026-10-04-shitu-验证记录.md)

### 安装与首次使用

1. 侧载本 Release 里的 `app-release.apk`
2. 打开 Shizuku → 给「拾图」授权（App 里点「请求授权」会弹窗）
3. 手机设置 → 应用设置 → 拾图 → **自启动：允许**、**省电策略：无限制**，并在最近任务里加锁
4. App 里新建规则：源目录选 `Android/data/<包名>/...`，目标默认 `/sdcard/Pictures/拾图`，**先用复制模式**
5. 确认目标目录里的图确实是你想要的，再切移动模式

> ⚠️ 系统更新（HyperOS 补丁 / Google Play 系统更新）后可能失效，请先跑一次「自检」。
