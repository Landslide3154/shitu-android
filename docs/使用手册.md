# 拾图 使用手册

> 这份是详细说明。只想快点用起来，看 [README](../README.md) 就够了。
> 版本以 [CHANGELOG](CHANGELOG.md) 和 [Releases](https://github.com/Landslide3154/shitu-android/releases) 为准。

## 一、它能做什么、不能做什么

**能做**：把某个文件夹里的图片，按你定的规则、自动、持续地搬到另一个文件夹。移动（原图离开原位）或复制（保留原图）都行。

**不能做**：搬视频/音频/文档；读写外置 SD 卡与工作资料；让 Shizuku 自己开机启动；把图片传到网上（除了「检查更新」请求 GitHub，其余全部离线）。

## 二、两种模式

拾图搬文件有两种身份：

| 模式 | 怎么来的 | 能访问 | 限制 |
| --- | --- | --- | --- |
| **普通模式** | 在「设置 → 存储访问」里打开系统「所有文件访问」 | `/sdcard` 下的普通目录（Pictures、DCIM、Download、Documents…） | 进不去 `Android/data`、`Android/obb` |
| **Shizuku 模式** | 装 Shizuku、启动并授权给拾图 | 包括 `Android/data/<包名>/` 里 App 私有的图片 | Shizuku 重启后要重新启动（非 root 手机一般靠无线调试） |

- 两条都可用时**优先用 Shizuku**（能进的地方更多），Shizuku 掉线会自动退回普通模式。
- 两条都不通时，规则不会跑；顶部状态卡会告诉你缺什么。
- 自检和目录选择器都走当前可用的那条通道，不会因为「没装 Shizuku」就整个 App 不可用。

## 三、第一次使用

1. 打开拾图 → 顶部状态卡确认可用（「本地模式」或「Shizuku 已就绪」）。
2. 点右下角 `+` →「空白规则」。
3. 填**规则名称**（必填）。
4. **源目录**点「选择」：从 `/sdcard` 开始，一层层点进图片所在的文件夹（如 `Android/data/com.qidian.QDReader/files/…`），点「选择此目录」。
5. **目标目录**同样点「选择」，建议 `DCIM` 或 `Pictures`（相册立刻能看到）。
6. 模式先选「复制」，间隔保持 5 分钟，点「保存并开始搬运」。
7. 等 5～10 分钟去相册看。确认没问题后再改成「移动」。

> 三样缺一不可：名称、源目录、目标目录。没填全就点保存，会弹提示告诉你还差哪几项，不会偷偷用「新规则」这种名字替你填。

## 四、四个页面

**规则页（首页）**
- 顶部：通道状态卡（颜色区分，点整块 = 跑一次自检）+ 累计已搬张数
- 右上角「简略 / 详细」：简略只显示名称和开关；详细显示源→目标、模式、间隔、后缀、上次运行、累计张数
- 卡片右上角开关单独管这一条；左下角复选框配合底部「全选 / 开启 / 停止」批量操作
- 卡上两个按钮：**立即运行**、**编辑**；长按卡片：复制一条、撤回已搬的图、恢复运行、删除
- 底部 `⋮` 对勾选的规则批量复制 / 撤回 / 删除
- 删除有两道保险：先弹窗确认，删完底部提示里还有「撤销删除」（约 10 秒）
- 右下角 `+`：空白规则，或套用你存过的模板（编辑页左下角「存为模板」）

**日志页**
- 每次真正搬动（移动 / 复制 / 失败 / 撤回）记一条；**跳过重复图片不记日志**，只计数
- 右上角 **筛选**：按结果类型、按规则筛选（收在弹出面板里，不占列表空间）；有筛选时会显示一行「已筛选」和「清除筛选」
- **导出** CSV（含完整路径，注意隐私）、**清除**（先问一次，只删记录）
- 后台搬完东西这一页会自己刷新

**编辑规则页**
- 三张卡：规则与源目录 / 目标与模式 / 频率与文件名
- 源目录、包含子目录、最大深度、目标目录、移动或复制、轮询间隔（1–30 分钟）、扩展名白名单、文件名后缀、按内容取名
- 配置有问题会在顶部显示橙色提醒（只报这条规则自己的、真会发生的问题）
- 改完按返回或切标签页，会先问「保存 / 放弃 / 继续编辑」

**设置页**
- 运行参数（默认收起）、**存储访问**（「所有文件访问」授权入口）、检测速度、开关、外观、自检、复制记录、关于
- **关于 → 检查更新**：联网查 GitHub 最新 Release，有新版会显示更新说明和「去下载」；网络不通会提示失败，不会卡住
- 外观：主题跟随系统 / 浅色 / 深色 + 动态取色（Material You）
- 复制记录：复制模式「这张图复制过没有」的账本，可查看条数并清空

## 五、文件名怎么定

**后缀**（管「能看出是哪个 App 来的」）：

| 你填的 | 效果 |
| --- | --- |
| `{app}`（默认） | 自动用来源 App 的名字：`封面.png` → `封面_起点读书.png` |
| 比如 `_拾图` | 固定后缀：`封面.png` → `封面_拾图.png` |
| 留空 | 不改文件名 |

**按内容取名**（新建规则默认勾上，老规则保持原样）：
- 名字主体换成 **15 位字母数字**，如 `K7pQ2mVx9Rb4TzW_起点读书.jpg`
- 这 15 位由文件内容算出来，同一张图永远同名 → 重复出现不会多存一份
- 字符集 `A-Z a-z 2-9`，去掉了容易看错的 `0 O 1 l I`
- 扩展名保留，后缀照旧叠加；算不出名字时退回原名并写一条日志，不会因此不搬

**永不覆盖**：目标已有同名文件时，自动加时间戳或序号（`封面_起点读书_20261004-101500.png`、`封面_起点读书_1.png`）。

## 六、复制模式为什么不会重复复制

复制模式按图片内容记一笔账：同一份内容只要复制过一次，以后不管哪条规则、哪个源目录再遇到都不再复制。
你后来把副本移走、改名、删掉都不影响——它记的是「这份内容已经拿过了」。

- 移动模式不受影响
- 设置 → 复制记录：可看条数、可清空（清空后同样的图会再复制一份进来）
- 同一文件重复扫描不会反复算哈希：同规则 + 同路径 + 同大小 + 同修改时间，第二次直接跳过

## 七、新图片多久能被发现

三层机制叠加（前两层默认都开）：

| 层 | 什么时候工作 | 多快 |
| --- | --- | --- |
| 快节奏检测 | 屏幕亮着且解锁，每 10 秒看一眼源目录变没变（只看目录时间，很省电），真变了才扫 | 十几秒 |
| 写完就搬 | 文件「大小 + 修改时间」两次没变（默认间隔 3 秒）就搬 | 几秒 |
| 按间隔轮询 | 一直工作（含熄屏），按每条规则自己的间隔整目录扫一遍 | 1–30 分钟 |
| WorkManager 兜底 | 常驻服务被系统清掉时 | 15 分钟 |

正在下载的文件不会被提前搬走。嫌慢：设置 → 检测速度，把间隔调到 3 秒。嫌费电：关掉「正在用手机时加快检测」。

## 八、默认参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 轮询间隔 | 5 分钟 | 每条规则独立 |
| 单轮扫描时间预算 | 20 秒 | 到点停止扫描，下次接着来 |
| 单轮最多搬运 | 20 个 | |
| 每分钟最多搬运 | 120 个 | |
| 单轮最长运行 | 60 秒 | |
| 文件稳定期 | 30 秒 | 刚生成/正在下载的文件先不动 |
| 重复抑制窗口/阈值 | 30 分钟 / 3 次 | 同名文件被搬走 3 次 → 判定自动重建，暂停该规则并通知 |
| 连续失败阈值 | 5 次 | 连续失败自动暂停 |
| 低电量暂停 | 开，15% | 低于 15% 或系统省电模式时暂停 |
| 日志保留 | 30 天 / 5 万条 | 先到者为准 |
| 扩展名白名单 | `jpg,jpeg,png,gif,webp,bmp,heic,heif,avif` | 大小写不敏感 |
| 加速清空 | 关 | 一轮结束立刻开下一轮（仍受每分钟上限约束） |

## 九、手机上还要做这几步

HyperOS / MIUI 对后台管得很严：

1. 设置 → 应用设置 → 拾图 → **自启动：允许**
2. **省电策略：无限制**
3. 最近任务界面给拾图**加锁**
4. 允许**通知**权限（常驻通知是它还在工作的标志）
5. Shizuku 也建议设「自启动 + 无限制」

## 十、常见问题

**规则开着但一张都没搬？**
① 顶部是否可用（「本地模式」或「Shizuku 已就绪」）② 点自检看哪项红 ③ 源目录里是否真有白名单后缀的图 ④ 图是否刚生成（稳定期）⑤ 看日志失败原因。

**显示「未授权」，点请求授权没反应？**
打开 Shizuku → 已授权应用 → 拾图 → 允许。或确认 Shizuku 正在运行。

**系统更新后突然不搬了？**
先跑自检。红了说明当前系统不允许这么读写 `Android/data`，等 Shizuku 更新；普通目录可改用普通模式。

**App 一直重建图片，反复搬？**
会自动暂停该规则并通知。把源目录选得更精确，或改用复制模式。

**撤回会出错吗？**
只撤回拾图自己搬的、你没改过、原位置还空着的文件；不满足就跳过并说明原因，逐条进行。

**会不会误删图片？**
不会。失败时源文件保持不动；移动模式校验失败会自动移回；从不覆盖已有文件。

**占多少电、多少流量？**
只有「检查更新」联网。平时每几分钟扫一次目录，只读文件属性不读内容；低电量自动暂停。

**怎么彻底卸载干净？**
先把规则停掉再卸载。已搬走的文件不会删；想退回用「撤回」或自己拖回去。

## 十一、隐私

- 除检查更新外**不联网**；不上传、不分析图片内容
- 文件只在你要的两个目录之间搬
- 日志与数据库存在本地应用目录，**不加密**；导出的 CSV 含完整路径，分享前留意
- 自检只用自己创建的临时文件，不碰真实图片

## 十二、给开发者

```powershell
# 环境：JDK 17+（本机 JDK 25）· Android SDK · Gradle 9.5.0（仓库自带 wrapper）
# 本机 dl.google.com 不通，依赖走阿里云镜像（已配在 settings.gradle.kts）

.\gradlew.bat :app:assembleDebug          # debug APK
.\gradlew.bat :app:assembleRelease        # release APK（签名取自仓库外 D:/keys/shitu-release.properties）
.\gradlew.bat :app:testDebugUnitTest      # JVM 单测
adb install -r -t app\build\outputs\apk\debug\app-debug.apk
```

技术栈：Kotlin · Jetpack Compose · Room · DataStore · WorkManager · Shizuku API 13.1.5
`minSdk 30 / targetSdk 36 / compileSdk 37`

代码结构：`core/`（命名/过滤/限速/去重/更新检查）、`local/`（普通模式的 java.io 通道）、`data/`（Room + DataStore）、
`shizuku/`（AIDL 桥 + shell 身份执行者）、`engine/`（单文件事务 / 一轮编排 / 撤回 / 自检）、
`service/`（常驻服务 / 开机 / 兜底 / 通知）、`ui/`（四页界面）

发版（只在本机手动做，不走 GitHub Actions）：

```powershell
# 1) 改 app/build.gradle.kts 的 versionCode/versionName + docs/CHANGELOG.md 加一段
.\gradlew.bat :app:testDebugUnitTest :app:assembleRelease
adb install -r app\build\outputs\apk\release\app-release.apk   # 装真机自己点一遍
git commit -F <utf8 消息文件> ; git push origin main            # 推送要用户明确同意
git tag -a v<版本> -m "<版本> <一句话>" ; git push origin refs/tags/v<版本>
# 2) 建 Release 并传 APK；附件地址必须手拼 uploads.github.com/repos/<owner>/<repo>/releases/<id>/assets?name=<文件名>
```
