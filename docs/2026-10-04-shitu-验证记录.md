## 1. 与规格/计划的偏差（以及为什么）

| # | 偏差 | 原因 | 影响 |
|---|---|---|---|
| D1 | `compileSdk` 由 36 提升到 **37** | Compose UI 1.12 / core-ktx 1.19 在编译期硬性要求 API 37，AGP 直接报错 | 仅编译期；`targetSdk` 仍为 36，运行行为与规格一致 |
| D2 | 仓库依赖走**阿里云镜像**，Gradle 分发用本机缓存 | 本机 dl.google.com 与 services.gradle.org 直连不通（TLS 失败） | 无功能影响；换机器/CI 需保留镜像配置或恢复外网 |
| D3 | Android SDK 组件从**腾讯镜像**手工解包安装（`D:\Android`） | dl.google.com 的 SDK 仓库不可达；`sdkmanager` 只能走官方源 | 已装 platform-tools / platforms;android-37 / build-tools;37.0.0 / cmdline-tools |
| D4 | AGP 9 内置 Kotlin，**不再应用** `org.jetbrains.kotlin.android` | AGP 9.0+ 应用该插件会直接失败并提示移除 | 构建方式变化，已在 README 写明 |
| D5 | Room 的 DAO 测试从 Robolectric 改为 **androidTest（真机）** | 避开 Robolectric 对 JDK 25 / API 37 的兼容不确定性，且真机就在旁边 | 覆盖更强；需接设备才能跑 |
| D6 | `RemoteFile` 放在 `com.landslide.shitu.shizuku` 包，并补一个 `RemoteFile.aidl` 声明 | AIDL 的 `parcelable` 声明必须与类同包，否则 AIDL 编译失败 | 无功能影响 |
| D7 | Shizuku 的类包名是 **`rikka.shizuku.Shizuku`**（Maven 坐标才是 `dev.rikka.shizuku:api`） | 实测 AAR 内类路径如此 | 无功能影响 |
| D8 | 必须在清单里声明 `rikka.shizuku.ShizukuProvider`（authorities=`${applicationId}.shizuku`） | 少了它 `Shizuku.pingBinder()` 永远 false（官方 demo 也这么声明） | 无功能影响 |
| D9 | 计划里任务 7/8 的示例测试与示例实现互相矛盾（稳定期、重复抑制、目标同名分支），本实现按**规格**为准重写了测试 | 例如：文件 mtime 不满足稳定期时计划中的测试仍期望搬走；「目标已有同内容文件」分支在计划的实现里永远不会触发 | 规格行为正确，测试与实现自洽 |
| D10 | `TransferExecutor` 在 MOVE 模式校验失败时**把文件移回源路径**（回滚） | 规格说「绝不误删」；rename 成功后校验失败若不回滚会丢文件 | 更安全，超出规格下限 |
| D11 | 新增 `FileBridge.describeEnvironment()` | 自检第 1/6 项需要环境信息；规格 §6.2 已有该 AIDL 方法 | 接口与 AIDL 仍一一对应 |

## 4. 已知限制（v1）

- `logs` 裁剪、`items` 中 SKIPPED 的 7 天清理已在仓储层实现，但清理只在"跑一轮"时顺带执行；长期不跑就不清理。
- 扫描游标按目录列举顺序做断点，目录内容变动剧烈时可能在极端情况下漏掉个别文件（下一轮会补上）。
- 目标目录文件名列举上限 500 条仅用于快速路径，最终是否重名一律用一次实时 `exists` 探测兜底。
- 未做 release 签名（任务 15）：keystore 需用户自己生成，配置未入库。
