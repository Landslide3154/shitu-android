# 0.12.4 设计补充：本地通道、检查更新、日志降噪与英文界面

> 日期：2026-10-17。面向后续维护者，解释"为什么这么做"。逐版用户说明见 `docs/CHANGELOG.md`。

## 1. 没有 Shizuku 也能搬：本地通道

**需求**：普通目录（`/sdcard/Pictures` → `/sdcard/DCIM` 这类）在不装 Shizuku 时也要能搬。

**方案**：新增 `local/LocalFileOps.kt` + `local/LocalFileBridge.kt`，用 App 自己的身份和系统「所有文件访问」
（`MANAGE_EXTERNAL_STORAGE`，Android 11+）直接做 java.io 操作。实现是 `ShituUserService` 的镜像：
迭代 DFS + 游标分页、`ATOMIC_MOVE` 优先、copy 校验大小、绝不覆盖、MOVE 失败撤销副本。

**为什么不用 SAF（用户选目录）**：SAF 的 URI 与现有规则里存的绝对路径是两套模型，混用会让规则、去重、
撤回都变复杂；而 `MANAGE_EXTERNAL_STORAGE` 保持路径模型不变，代码几乎是复制。

**通道选择**（`ShituApp`）：

```
channel() = Shizuku READY ? SHIZUKU : (本地可用 ? LOCAL : NONE)
fileBridge = Shizuku READY ? ShizukuBridge : LocalFileBridge
ensureChannel() = 先试连 Shizuku，连不上再看本地权限
```

- 有 Shizuku 优先用它（能进 `Android/data`）；掉线自动退回本地。
- 两条都不通时规则不跑，但 UI 明确说明缺什么，不再显示"Shizuku 未就绪"就完事。
- `Android/data`、`Android/obb` 即使在本地模式下也读不到——这是系统限制，不是实现缺陷。

**取舍**：清空「复制记录」账本时，同时删除复制模式规则的完成条目（`items` 里 MOVED/COPIED）。
否则「同路径 + 同大小 + 同 mtime 直接跳过」的快速判定还会命中，用户会看到"清空没生效"。

## 2. 检查更新

- 纯逻辑在 `core/UpdateChecker.kt`：自带最小 JSON 解析器（不引依赖、JVM 可测），
  `parseRelease` / `isNewer` / `fetchLatest`（固定仓库地址，防篡改下载源）。
- 需要 `INTERNET` 权限，但只用于这一个请求：`api.github.com/repos/Landslide3154/shitu-android/releases/latest`。
- UI 在「设置 → 关于 → 检查更新」；`fetchLatest` 是阻塞调用，接线时放 `Dispatchers.IO`。
- 不做自动后台检查、不做应用内下载安装（交给浏览器/系统安装器），减少权限与复杂度。

## 3. 日志降噪

**现象**：复制模式每轮重扫，每个已复制文件写一条「跳过」日志，日志页几乎全是跳过。

**改动**（`engine/RuleEngine.kt`）：
1. 内容账本命中、目标已存在同内容（`ItemStatus.SKIPPED`）→ 只 `skipped++`，**不写日志、不写 items**。
2. 新增快速跳过：`ContentLedger.handledBefore(ruleId, srcPath, size, mtime)`，同规则 + 同路径 + 同大小 + 同 mtime
   才命中；放在算 SHA-256 之前、限速之前（跳过不占单轮搬运配额，否则大目录里新图永远轮不到）。
3. 只对 COPY 模式启用快速跳过（MOVE 模式源文件已消失，命中只可能是"原样重建"，没有优化价值）。

历史已写入的跳过日志不会删，只是不再新增。`RunSummary.skipped` 与界面计数不变。

## 4. 日志页筛选

结果/规则两排常驻 chip 占掉列表空间 → 收进右上角「筛选」按钮（`ModalBottomSheet`），
有筛选时显示一行"已筛选…"与「清除筛选」。导出/清除保留在右上角。

## 5. 新建规则

新规则三项全空（名称、源目录、目标目录）；保存时统一校验并弹窗列出缺项。
目录选择器：当前值为空时从 `/sdcard` 开始，已有值从当前目录开始（编辑老规则少点几层）。

## 6. 中英文界面

- 默认资源 `res/values/` = **英文**；`res/values-zh/` = 中文。非中文系统自动显示英文，
  中文系统显示中文（不再出现"外国用户看到中文"的情况）。
- 字符串按区域拆成多份：`strings_app.xml` / `strings_rules.xml` / `strings_edit.xml` /
  `strings_logs.xml` / `strings_settings.xml`，避免单文件冲突。
- `StatusMap` 返回 `@StringRes Int`（便于 JVM 单测断言）；`Labels` 接收 `Context`。
- **已知限制**：通知、日志里的事件说明、自检详情、冲突提醒仍只有中文（属于运行产物，
  不在界面资源层），后续版本再抽。

## 8. 顺带修的分页漏洞

`ShituUserService.listFiles` 与 `LocalFileOps.list` 的游标分页：after 之前的目录在重建遍历时不入栈，
若游标正好停在子目录上，下一页会漏掉整棵子树。两边都改成"只不发射、仍入栈"。
